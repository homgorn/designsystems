# AGENTS.md — правила проекта designsystems (обязательны для ВСЕХ агентов)

## 0. Запрет удаления (высший приоритет)

**НИЧЕГО не удалять без двойного подтверждения человека.** Особенно: `db/`, `research/raw/`, `wiki/`, спеки, тесты.
Файлы удаляются только после явного `ДА, УДАЛЯЙ <путь>` от человека в чате. Переименование/перемещение = тоже подтверждение.
Архивировать — в `archive/` (создать при нужде), не `rm`.

## 1. Метод

SDD + spec-kit + BMAD: данные (`research/`) → синтез (`wiki/`) → спеки (`specs/`) → код (`engine/ modules/ adapters/`) → тесты → чейнджлог.
**Spec-first:** без апрува спеки кода нет (см. spec-driven-workflow-alireza). Тесты из AC — до реализации (красная фаза).

## 2. Скиллы и агенты

- Исследование: `deep-research-alireza` (гипотезы → ≥3 разнотипных источника → адверсариал → refresh targets).
- Рынок: `competitive-teardown-alireza` (12 измерений, evidence к каждой оценке).
- Продукт: `marketing-product-ideas-mia`, `product-positioning-mia`, `portfolio-positioning-mia`.
- Стиль: `technical-writing-cursor` + humanize при пользовательских текстах.
- Субагенты: задачи только из `tasks/BOARD.md`; отчёт — что сделано + файлы + тесты + уверенность /10.

## 3. Качество

- Уверенность /10 к каждому факту; нет данных → `[нет данных]`; оценки → `[оценка]`.
- Факт из БД = 9/10 со ссылкой `db:<таблица>/<slug>`; трафик/выручка без источника ≤ 5/10.
- CC BY 4.0: каждый экспорт — атрибуция `DesignSystems.one (2026)` + `checked_at`.
- Python ≥ 3.11, ruff, тесты зелёные (`make test`), секреты только в env.
- Расхождение 11 000 vs 300–2 000 vs 2 879 — приводить все три числа, не замалчивать.

## 4. Эскалация (stop-and-ask)

Scope creep · >30% неоднозначности · breaking changes · security/PII · неизвестные perf-характеристики · кросс-зависимости.
Формат: блок **Blocked on / Question / Options A-B / Recommendation / Impact**. Без рекомендации не эскалировать.
